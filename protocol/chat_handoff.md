# Протокол передачи между двумя независимыми чатами

Чаты не разделяют контекст автоматически. GitHub — общий источник истины только в той мере, в какой конкретный чат может читать актуальные файлы. Если доступа нет, пользователь передаёт текст задачи или отчёта вручную.

## Поток
1. Учитель создаёт задачу в tasks/.
2. Библиотекарь читает задачу и возвращает отчёт по templates/report.md.
3. Отчёт сохраняется в reports/ через GitHub-инструмент либо передаётся пользователю текстом.
4. Учитель проверяет отчёт и создаёт отзыв по templates/review.md.
5. Только принятые выводы могут стать учебными заметками в knowledge/.
6. Пользователь или чат с подтверждённым доступом сохраняет заметки и отчёты в репозиторий.
7. Следующая задача ссылается на ID предыдущих результатов.

## Формат передачи
    message_id: MSG-YYYYMMDD-001
    task_id: TASK-YYYYMMDD-001
    from: teacher|librarian
    to: librarian|teacher
    type: task|report|review|correction
    status: draft|ready|accepted|changes_requested|rejected
    reply_to: null
    created_utc: YYYY-MM-DDTHH:MM:SSZ

Если автоматическая запись невозможна, чат выдаёт законченный текст и точный путь файла. Пользователь копирует его в GitHub или передаёт другому чату. Не выдавать ручную передачу за автоматическую интеграцию.


## Обязательный контроль готовности
Не оценивай готовность по числу файлов или ссылок. Проверяй источники, подтверждение конкретных тезисов, независимость данных, возражения, ограничения и незакрытые пробелы. Используй статусы `READY_FOR_PILOT_BY_TOPIC`, `PARTIALLY_READY_WITH_CAVEATS`, `NOT_READY`. Готовность определяется по конкретной теме. Отмечай только реально выполненные проверки; если действие или инструмент недоступен, прямо фиксируй ограничение. Не утверждай, что автоматическая передача между чатами или автономный поиск работает без подтверждённой настройки.
